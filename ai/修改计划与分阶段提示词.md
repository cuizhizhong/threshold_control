## 0 先看这三条

**① 防御性写作的源头在仓库根目录的 `AGENTS.md`。**
它的“写作风格”一节要求“结论不要写满”“对尚未确定的结论，写成观察、问题或待检验假设”“写作语气克制，像研究者在整理思路”，并推荐“该现象提示……但仍依赖于……”“该设定可能在……情形下失效”这类句式；“当前研究与验收口径”一节又列了大量限定条件。Codex 每次进入仓库都会先读这份文件。只要它不改，任何“去防御化”的提示词都会和它冲突，AI 会一边删一边加回来。阶段 0 用一份重写的 AGENTS.md 整体替换它。

**② 正文有一部分文字归复现管线管，而不归你管。**
`reproducibility/` 里的 `paper_sync.py`、`icu_revision_text.py`、`threshold_revision_text.py`、`joint_extra/manuscript.py` 等脚本把整段中文按锚点写进 tex（例如“该结果为解析公式回代，不是独立 ODE 积分验证”这句就写在 `paper_sync.py` 里）；正式稿由 `manuscript_versions/current.json` 用 SHA256 锁定，`tests/` 里还有检查文字锚点的测试。`run_all` 构建时使用 `current.json` 批准的稿源，而不是 `latex/` 里的当前文件；`publish_verified.py` 发布时会把管线产物拷回 `latex/`（旧文件另存备份）；`threshold_revision_text.py` 等脚本还按 SHA256 钉住 `latex/` 下的 tex。因此在 `latex/` 里直接改，管线不认这些改动、下一次发布会把它们替换掉，而根目录 AGENTS.md 的“发现差异须同步全部依赖”会把 AI 拖进审计流程。**已决定**：在 main 上删除这一层（清理前的全部内容保存在标签 `pipeline-final-20261006`），论文移到 `paper/` 直接编辑，计算代码和结果保留（见阶段 0）。

**③ DeepSeek 的方案方向基本对，但有几处照做会出错**（见第 2 节），最严重的是“把 $I_{\rm cum}$、$I_{t_{\rm cum}}$ 统一成一个记号”——它们是不同的量。

## 1 工具与工作方式

**结论：用能直接操作仓库的智能体（Codex 或 Claude Code），不要在聊天窗口里贴 tex。**
稿件约 2160 行、250 多处交叉引用，改动要跨文件、要编译验证、要能逐行看 diff；聊天窗口不能编译，也很难保证“移动”时不丢内容。但“删什么、留什么、第 9 节放哪”这类判断应由你拍板，智能体只负责执行和报告。

工作约定（每个阶段都适用）：

1. **一个阶段一个新会话。** 阶段之间靠仓库里的文件传递状态（`paper/revision_notes/`），不靠聊天记忆。上下文过长时直接开新会话，让它先读 `AGENTS.md` 和 `paper/revision_notes/`。
2. **每阶段结束必须：编译通过 → 写修改记录 → `git commit`。** 你看 `git diff` 和 PDF，满意再进入下一阶段；不满意就回退到上一个提交重做。
3. **结构和文字分开改。** 先只搬不改（阶段 2），再逐章改写（阶段 4）。两者混在一起时，你无法判断一段话消失是“移走了”还是“删掉了”。
4. **引言、摘要、题目最后写（阶段 6）。** 它们概括的是改完以后的正文。
5. **在能编译的环境里跑智能体。** 你的编译链（xelatex + biber，PowerShell）在 Windows 本机。云端容器里多半没有 TeX，若在云端运行，每阶段结束后需要你在本机编译确认。
6. **Codex 读 `AGENTS.md`，Claude Code 读 `CLAUDE.md`。** 仓库根目录两份都放（`CLAUDE.md` 只写一行 `@AGENTS.md`），两种工具共用一份规则。每个阶段的提示词也都要求先读 `AGENTS.md`，不依赖工具的自动加载。
7. **只有一份规则文件。** 新的根目录 `AGENTS.md` 约 16 KB，改写示例单独放在 `paper/style_examples.md`。Codex 会把从根目录到当前目录的各级 `AGENTS.md` 拼接读入，并有总长度上限（以你所用版本的文档为准）；以后往里加内容时注意长度，过长的部分会被截掉而 AI 不会提示。子目录里各计算模块的旧 AGENTS.md 只在 Codex 进入那些目录时才会被读到，投稿修改期间用不到。

### 3.3 写作问题

正文中以下表达的出现次数：「不能」41、「不是」27、「核查」12、「不表示」9、「据此」9、「不直接」8、「并不」7、「无需」6、「名义」5。典型类型：

- **作用域的反复声明**：“类内”“规定控制类”“固定起止状态”在 2.2 节、第 6 节开头、6.2 节末、6.4 节多处、7.2 节和 10.1 节反复出现。
- **元评论**：如“这一判据由式(4.12)乘以正因子后整理得到，无需再为右端引入符号”“式(4.8)可直接积分，不必另设原函数记号”。
- **审计语言**：「核查」「对账」「随文复现说明」「名义」「不是独立 ODE 积分验证」——这是复现管线的口径，不是论文的口径。
- **否定式铺垫**：用“不是 X，而是 Y”“并不据此……”开头，而不直接陈述 Y。
- **数值段落逐点罗列**：7.2–7.4 节一段内有 9–14 个数字，精确到 4 位小数。
- **术语漂移**：阈值控制期 / 平台期 / 感染平台；控制时长 / 控制持续时间；隔离率 / 隔离比例；仅隔离 / 仅加强隔离 / 隔离率阈值控制；类内最小成本 / 最低成本分配 / 类内最低二次成本分配 / 成本最小分配；清零时间 / 动态清零时间 / 社区动态清零时间 / 清零时刻。2.1 节“文中沿用的‘隔离率’指比例 $q$，不是检出感染者的连续时间风险率”这句，本身就是术语没统一留下的补丁。

## 5 写作规范（`AGENTS.md` 与 `paper/style_examples.md` 中有相同内容）

### 5.1 限定性表述分五类处理

| 类别 | 判别 | 处理 |
|---|---|---|
| A 定理假设 | 去掉后结论不成立，如 $0<\beta<1$、$\eta>1$、条件(2.11)、“无额外能力限制” | **保留在定理陈述里**；摘要、引言、结论转述时也要带上 |
| B 作用域 | “类内”“固定起止状态”“规定控制类” | 在 2.3 节**定义一次**控制类 $\mathcal A(\eta)$，之后用术语承载，删除其他各处的重复声明 |
| C 方法局限 | 无回流假设、观测误差与执行延迟、$J$ 不计隔离人天、有效人口未知、阈值未经临床标定、长期外推 | **集中到 7.2 节**，正文、图注、表注中删除 |
| D 冗余与元评论 | “无需再引入”“不必另设”“这里没有据此断言”“并不意味着”等 | **删除** |
| E 未完成的工作 | “尚待核查”“未进一步确定”“候选” | **不许靠改写消除**。列入“待作者确认”，由你决定补算还是删去该结论 |

### 5.2 改写示例（原文均取自当前稿件）

**例 1　元评论 → 删除**
- 原：特别地，若右端不大于零，则导数严格为正。这一判据由式(4.12)乘以正因子后整理得到，无需再为右端引入符号。
- 改：特别地，右端非正时 $\partial\Delta t/\partial c_0>0$。

**例 2　作用域的重复声明 → 用定义承载**
- 原（命题 2.2 之后）：命题 2.2 中的最晚启动只相对于首次加强前未被改变的常规轨迹；最早退出只相对于已选定的恒定感染轨迹，不比较不同轨迹的退出时间。等式(2.3)表示感染增长恰好为零，既不唯一确定双控制分配，也不等于瞬时或累计成本最小。本文以这一规定过程作为研究对象，并不据此证明它在全部满足 $I\le\eta$ 的控制中最优。实施能力不足、观测误差或响应延迟存在时，可能需要提前干预或预留安全余量。
- 改：**定义 2.3**（阈值控制类）　记从 $(S^*,\eta)$ 出发、在 $[t_1,t_2]$ 上满足(2.2)、并于首次到达 $S=S_c$ 时恢复 $(c_0,q_0)$ 的控制全体为 $\mathcal A(\eta)$。下文的“最短”“最少”“最优”均指在 $\mathcal A(\eta)$ 内。由(2.3)，$\mathcal A(\eta)$ 只约束乘积 $c(1-q)$，一般包含多种分配；第 4 节比较这些分配。
- （“观测误差、响应延迟”移入 7.2 节。）

**例 3　显式族的免责 → 一句定位**
- 原：这一子族用于给出可计算的控制和两种单控制之间的连续分配，不代表全部联合控制，也不声称它是唯一可以显式求解的选择。下面的比较与成本最小化均返回全部允许的 $c_c(S)$。
- 改：该族连续连接两种单控制，数值部分以 $\alpha=0.5$ 作参照；以下比较和成本最小化均在整个 $\mathcal A(\eta)$ 中进行。

**例 4　否定式解释 → 正面陈述**
- 原：$\lambda$ 较大表示下降最快的时刻相对靠后，不能据此判断绝对时刻 $t_{\rm inf}$ 的变化，也不将其解释为前后阶段累计放松量的比例。

**例 5　研究缺口 → 正面表述**
- 原：单一传播系数模型中的结果不直接包含未感染者隔离的代价，预设分段控制或数据重构也不能代替对全部允许分配的分析。
- 改：单一传播系数模型无法区分未感染者隔离的代价，分段常数控制和数据重构只考察特定的控制路径。本文在区分感染与未感染被追踪者的模型中刻画全部允许分配。

**例 6　数值段落中的澄清 → 括号或删除**
- 原：这里的一致只指同一易感者状态下的控制：受限分配到达同一 $S$ 的时刻较晚，$I_q$、$S_q$ 等状态也不同，并非相同时刻的完整轨迹相同。

**例 7　审计语言 → 论文语言**

### 5.3 句式、段落与数值

- 每节开头 1–3 句：本节回答什么问题、主要结论是什么。不写“本节先……再……最后……”式路线图（引言末段除外）。
- 定理之后最多 1–2 句说明含义或机制，不复述证明，不写“该结论只刻画……不证明……”。
- 证明保留逻辑完整，删除“在本证明中记”“下面说明”之类的过渡；长证明移附录，正文写“证明见附录 A”。
- 一句话一个论断；不用分号串起三四个从句。
- 数值段落按“现象 → 机制 → 对应的理论结果”写。正文一段不超过 3–4 个数字，保留 3–4 位有效数字；精确值留在表中，正文数字与表一致。同一结果只在一处给出完整数字。
- 用“本文”，不用“本稿”；“数值计算/数值验证”代替“核查”；“开环控制”代替“名义控制”。
- 不加空泛评价词（“深刻”“系统性”“重要意义”），也不为了“保险”新增限定语。

## 7 常见失败与应对

| 现象 | 应对 |
|---|---|
| AI 删掉了定理条件，或在摘要里把“类内最优”写成“最优” | 阶段 7 第 3 项专门检查；发现后回退该段 |
| AI 改了数字，或四舍五入后与表格不一致 | 每阶段跑 check_tex.py；数字只能来自 baseline 或 `reproducibility/results/` |
| AI 顺手“修正”了推导 | 规则要求只报告不修改；看 diff 时重点看定理和公式块 |
| AI 编造文献 | 只允许从 `refs/` 的 PDF 取信息，新增条目须你确认 |
| AI 开始改 `reproducibility/` 或跑测试 | 规则已禁止；若发生，丢弃该会话的提交 |
| AI 为了“简洁”删掉证明 | 规则写明证明只能精简或移附录 |
| 改写后又长出新的限定语 | 阶段 7 第 5 项计数；提示词里已写“不新增任何限定语” |
| 会话上下文用尽 | 开新会话，从 `revision_notes/` 和 git 恢复 |
