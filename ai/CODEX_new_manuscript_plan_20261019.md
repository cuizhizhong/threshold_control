- `NEW_4_zh_review.md`：相对底稿的主要变化、数学差异、数字差异、编译与测试摘要、作者应重点阅读的位置。
- `NEW_author_inputs.md`：仅保留确需作者补充或判断的项目。
- 清晰本地提交历史；不推送 main。

此时名称为“中文审阅版”。作者审阅后再把指定提交标记为 `zh-final`；已有同名标签时不移动或覆盖，使用新的有日期标签并登记。不能把“编译成功”自行写成“作者已验收”。

## 九、NEW-5：英文稿，分四个工作段完成

启动提示词：

~~~text
我已审阅中文新稿，请以我指定的中文提交或冻结标签为唯一基准，执行本计划 NEW-5。开始前记录实际基准；按当前官网要求准备 BMB 英文稿。保持数学和数字含义，允许英文行文重组。先制作完整稿件，再集中报告需要我判断的问题，不要求每一章分别审批。
~~~

### 9.1 英文目录与单一来源

在 `paper_en/` 建立主稿、补充材料、章节与构建入口。模板使用 Springer Nature 官方来源；Codex 可在允许联网时从官网取得并记录来源，不必把“作者手动下载模板”设为前置障碍。

工作稿的数字来自同一 `paper/generated/nr_numbers.tex`，图来自同一正式图目录。根据实际编译工作目录设置相对路径并验证；不能只写一个看似正确的 `\input` 就认为可构建。

参考文献优先共用一个来源文件。若模板要求拷贝，增加同步核对，避免两个 bib 独立演化。投稿包再复制所需文件，保证脱离中文目录也可编译。

采用冻结稿的术语表；统一“组合”及所用英文表达，避免中文禁止的术语在英译中重新引入。“移出者”使用 removed，\(I\) 对应社区非隔离感染者存量。

### 9.2 四个工作段

| 工作段 | 内容 | 核验重点 |
|---|---|---|
| NEW-5a | 模板、术语、题目、摘要、引言及第2节 | 贡献与范围、仓室含义、参考文献 |
| NEW-5b | 第3–5节及证明附录 | 条件、量词、严格性、局部/全局、终点 |
| NEW-5c | 第6–9节及全部补充材料 | 数字单位、图表、回流解释、案例的证据等级 |
| NEW-5d | 全文连贯性与期刊格式 | 引用、重复、数学对应、单独可读的图表注 |

每段可建立一个提交，记录可恢复的进度。不同会话续写时先读上一记录，不从头重新翻译。

### 9.3 英译取舍

- 先保持九章和现有附录位置，不默认把 3.2、3.4、4.2 整节迁移。完整英文稿形成后，如篇幅确实阻碍主线，再提出具体移段草案。
- 不全局替换符号。先确认是否确有歧义，再局部更名并维护旧新记号对照。
- 数字显示按用途决定：一般比较可适度减少有效数字；小差异、权重括区、尾界、复核表和接近边界的量保留必要精度。不能把所有表机械改为三位有效数字。
- 建立标签对应表核对数学对象。排版后的中英文编号不必机械相同；必须能准确映射且各自引用正确。
- 作者信息等未提供项留在待办，不填虚构值。带占位符稿件可供审阅，但不能标成已可提交。

### 9.4 期刊格式核查

BMB 官网当前要求包括：摘要 150–250 词、关键词 4–6 个、作者—年份引用和按作者字母顺序的参考文献、连续行号及页码、可编辑源文件和编译 PDF、相关声明与数据可得性说明。执行时再次核对官网并按实际模板落实。[R7]

记录真实的 AI 协助范围，按届时政策形成适用的披露草稿，由作者确认；语言润色与实质生成、分析不能混写。不得保证某种篇幅、英文修改或模板选择会带来更快接收。

### 验收与输出

- 全部英文正文和补充完成，可独立理解，无草稿占位段落。
- 数学对象、条件、公式、图表数据均能映射回冻结中文稿。
- 关键术语、参考文献和图表一致，实际编译及 PDF 视觉检查完成。
- 输出英文主稿/补充 PDF 和 `NEW_5_en_review.md`。
- 如英译发现中文实质错误，登记并同步修订明确版本，不能让英中文悄悄分叉。

## 十、NEW-6：可分发快照、投稿材料与最后的合并

### 10.1 独立构建的投稿包

新建 `paper_en/submission/` 或同用途打包目录，复制实际使用的 tex、模板样式、bib、数字宏和图。改写包内路径后，在脱离父目录的新临时目录构建主稿与补充。

输出主稿 PDF、补充 PDF、源文件包及包内文件清单；用实际引用确定包含范围，不把整个仓库压缩成投稿附件。补充文件应包含题名及作者信息，并在主文按期刊要求引用。

### 10.2 可复现快照

采用明确包含清单，提供本稿实际使用的计算代码、固定参数、可分发输入数据、JSON 结果、图表映射和运行说明。

- 仅为内部查阅而存放的出版社 PDF、电子书和讨论记录不自动装入新发布快照。
- 真实数据的来源、许可或访问限制由作者给出。已可公开的数据按其要求署名；不能再分发的输入提供获得方法和可公开的派生结果。
- 用“无 .git 的新目录”执行 NEW-1、NEW-2 的导数、尾界及宏生成验收。
- 一个结果有固定数据与核验入口即可，不强制一个图对应一个新脚本；如某图不能从所提供材料重建，声明中如实限定，不写“全部图表完全可复现”。
- 开发仓库继续保留历史与来源标签；公开快照不因而必须携带全部历史。
- 是否建立公开 release、Zenodo DOI 或上传数据由作者选择。准备好本地文件与说明后再进行授权发布，不凭空填写链接。

### 10.3 投稿文字

准备一页左右英文投稿信草稿，依次说明：

1. 双渠道在给定阈值平台上的科学问题；
2. 状态参数化、能力可行性、平台计数取舍与成本优化；
3. 无回流作为可解析基准，补充材料说明允许返回后的长期限制；
4. 最优性是在明示策略类中的最优性。

不把一般正回流排序、\(S_{\rm sw}\) 的全局权重无关性或未经证明的 ICU 保证写入投稿信。另一篇论文或预印本只有确已存在、确需说明时才提，不作为本稿投稿条件。

准备实际适用的作者信息、基金、利益冲突、作者贡献、数据与代码可得性等声明草稿。无法确定的事实由作者填写。期刊如要求推荐审稿人，再列基于主题匹配且需核实利益冲突的候选，不自动发送邮件或邀请。

### 10.4 最后再更新 main

新稿、复现快照和投稿材料完整后，先交作者审阅具体提交、PDF 和待填事实。更新 main 是之后的单独动作。

如作者明确要求更新 main，执行前再读取：

- 新稿分支目标 SHA；
- 本地 main、origin/main 的当前 SHA；
- main 工作区是否干净；
- `git merge-base --is-ancestor main paper/submission-ready` 的结果。

可快进时，用 `git merge --ff-only`；不可快进时，先展示独有提交和冲突处理方案，不能自动强制推送或丢弃 main 独有工作。推送必须使用已获授权的目标；不删除任何研究分支或溯源标签。

### 最终完成标准

“新稿已整理好”要求：中文和英文稿件完整、来源清晰、已知定点问题关闭、可编译、必要数字可再生成，并交作者审阅。

“可以投稿”还要求：作者、基金及各项声明补齐，所有必要输入与公开链接真实有效，作者确认最终内容。

“已投稿”只有作者实际完成期刊提交后才记录。本计划不自动登录投稿系统或代作者点击提交。
