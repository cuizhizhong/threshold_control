## 用途

本文件夹用于西安疫情控制策略的理论与数值分析，主要比较三类策略：

- `TDINN控制`：来自 He--Tang--Xiao (2023) 论文学习得到的控制函数；
- `情景一阈值控制`：由本文情景一理论推导得到的阈值控制；
- `常规控制`：反事实基准，满足 `c(t)=c0` 且 `q(t)=q0`。

本文件是西安控制比较原模块的局部上下文记忆。处理本目录时同时遵守项目根目录 `AGENTS.md`。本文件的历史实验细则仅用于解释相应历史输出，不得覆盖正式稿、正式复现设置、原始数据及冻结来源的保护规则。

当前阶段不是正式写论文结论，而是继续做理论分析、数值实验和图像比较。不要急于证明某个控制策略一定更好，应先把不同参数、不同成本函数和不同控制设定下的数值现象计算清楚。

## 研究目标与当前状态

当前目标不是下结论“情景一阈值控制优于 TDINN 控制”。当前目标是构建单阈值控制的参数图谱，系统分析：

- 阈值 `eta` 如何影响启动时间、控制时长、清零时间和累计感染；
- 阈值 `eta` 如何影响隔离率轨迹 `q_c(t)` 和控制成本；
- 低阈值控制是否表现为长期常态化管控；
- 二次加权成本函数下，TDINN 控制、情景一阈值控制和常规控制的成本排序是否变化；
- 不同常规接触水平 `c0` 下，情景一阈值控制自身的行为边界。

低阈值导致控制时间很长时，不要直接判定其“不合理”。在实验阶段，应先把它作为一种可讨论情形保留：它可能对应长期低感染水平维持或常态化管控。是否现实可行，应在后续结合成本、持续时间和政策含义进一步判断。

目前更严谨的研究口径是：

> 先系统刻画单阈值控制在不同 `eta`、成本函数和 `c0` 下的行为边界，再讨论它相对于 TDINN 控制和常规控制的优劣条件。

## ICU 容量解释

模型中的阈值约束对象是社区感染者 `I(t)`，不是 ICU 患者数。因此若需要解释现实医疗容量，不要直接设：

```tex
\eta = B_{\rm ICU}.
```

若使用医疗容量的比例参考情景，应区分名义床位与扣除其他病种占用、预留余量后的可用容量。例如：

```tex
\eta = \frac{C}{\rho_{\mathrm{ICU}}},
```

其中 `C` 是所选情景中的可用 ICU 容量，`rho_ICU` 是单位社区感染人数对应的参考床位需求系数，不直接等于某个感染者最终进入 ICU 的概率。该比例需要来源和移植假设，不能替代重症进展、入院延迟和床位周转模型；隔离感染者的医疗需求同样不能忽略。

因此，520 或 1300 这类 ICU 床位数不能直接作为 `I(t)` 的最终现实阈值解释。

但当前阶段主要进行理论和数值实验。若用户要求先做低阈值扫描，可以暂时把 `eta=100,520,1300` 等作为数学阈值或压力测试点，不必在实验阶段立即完成现实含义解释。

## 情景一控制实现

除非用户明确要求设计新的控制策略，情景一阈值控制必须保持为理论推导得到的时间开环控制。

控制函数为：

```tex
q_c(t)=1-\frac{\gamma N}{\beta c_0 S_{\rm th}(t)}.
```

其中 `S_th(t)` 是在计算 `S_star` 和 `t1` 后得到的理论时间轨迹。

不要把 `q_c(t)` 写成使用数值积分中实时 `S(t)` 的状态反馈函数。

控制阶段为：

1. 常规控制直到 `I(t)=eta`，得到 `t1`；
2. 平台控制阶段，使 `I(t)=eta`；
3. 当 `S(t)` 到达 `S_c` 后回到常规控制；
4. 继续模拟到动态清零，即 `I(t)<=1`。

## 低阈值现象

一个常见质疑是：`eta=0.002N` 时控制启动较晚。这个判断是对的，因为阈值控制定义为 `I(t)` 达到 `eta` 后才启动。

降低 `eta` 后，必须同时观察启动时间、控制时长、清零时间、累计感染和控制成本，不能只看启动时间。

控制时长公式为：

```tex
\Delta t
=
\frac{N}{c_0\eta}
\log\frac{S^*-\bar S}{S_c-\bar S}.
```

当 `eta` 降低时：

- `t1` 会提前；
- `S_star` 会略微增大；
- 对数项会缓慢增大；
- 主导影响来自 `1/eta`；
- 控制时长和清零时间可能急剧增加。

原模块历史设置下的典型结果（不是当前正式稿结果的新一轮验收）：

- `eta=26326`：`t1≈16.90`，控制时长约 `85.07` 天，清零约 `258.11` 天；
- `eta=100`：`t1≈11.38`，控制时长约 `22523.29` 天，清零约 `23748.32` 天。

因此，降低阈值虽然能提前启动，但可能明显延长平台期。当前阶段不要直接把这种结果判定为“不合理”，而应把它作为低阈值长期控制或常态化控制的一种数值现象，继续结合成本函数和持续时间进行比较。

## 有效再生数解释

有效再生数定义为：

```tex
R_e(t)=\frac{\beta c(t)(1-q(t))S(t)}{\gamma N}.
```

常规控制下初始值约为：

```tex
R_e(0)\approx 4.43>1.
```

因此，常规控制反事实下可以出现很高的感染峰值。这是模型给出的反事实结果，不表示 TDINN 拟合错误。

情景一阈值控制下：

- 控制启动前，由于 `S(t)` 几乎没有消耗，`R_e(t)` 维持在较高水平；
- 平台期内，设计的 `q_c(t)` 使 `R_e(t)≈1`；
- 平台结束后，`S(t)` 接近 `S_c`，因此 `R_e(t)<1`。

当阈值很低时，`q_c(t)` 下降缓慢，是因为 `I(t)=eta` 很小，导致 `S(t)` 消耗很慢。

## 控制成本指标

主要成本指标统一记为二次加权总成本：

```tex
J
=
\int_0^T
\left[
w_c\left(\frac{(c_0-c(t))_+}{c_0}\right)^2
+
w_q\left(\frac{(q(t)-q_0)_+}{1-q_0}\right)^2
\right]dt.
```

默认权重为：

```tex
w_c=1,\qquad w_q=2.
```

单独的归一化分项成本作为参考指标保留：

```tex
J_c=\int_0^T \frac{(c_0-c(t))_+}{c_0}\,dt,
```

```tex
J_q=\int_0^T \frac{(q(t)-q_0)_+}{1-q_0}\,dt.
```

其中 `(x)_+=max(x,0)`。不要把 `J_c+J_q` 作为综合成本，也不再使用旧的线性综合指标或平均日成本。低阈值控制是否代价较高，主要看总成本 `J`；`J_c` 和 `J_q` 只说明成本来自接触率降低还是隔离率提高。

旧 `xian_control_comparison.py` 采用人数状态和旧绝对容差，不能将其直接运行结果称为统一 DOP853 结果。MATLAB、拐点求积和联合控制候选比较另有各自设置；上述统一积分口径不意味着全文共用一个求解器或容差。

拟合得到很小的 `I0` 是正常现象。应解释为模型校准种子，而不是现实中的整数病例数。

## 暂不主动推进的方向

暂不主动推进双阈值控制，除非用户明确要求。

双阈值或预警阈值思想可以作为未来扩展保留：

基本思想是：

```tex
\eta_{\rm warn}<\eta_{\rm cap}.
```

其中：

- `eta_cap` 表示给定的社区感染人数上限，不无条件等同于实际医疗容量；
- `eta_warn` 表示提前启动控制的预警线。

这个方向可用于回应“基准阈值启动较晚”的问题，同时避免直接降低容量阈值导致平台期过长。

注意：

- 这不再是原始情景一纯解析控制；
- 如果依赖实时 `I(t)`，它属于反馈控制；
- 如果保持开环，则需要新的预设时间或渐进控制设计。

当前阶段先分析单阈值控制，不要因为基准阈值启动较晚就立即切换到双阈值策略。
